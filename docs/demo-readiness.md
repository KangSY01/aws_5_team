결정 (11/20)
- 장면 1 일정은 **데모 캐시**로 대본 일정(흰여울 → 자갈치 → 해운대 → 빛축제 17:30)을 돌려준다 — A → ✅ 완료 (#54). `DEMO_CACHE_ENABLED=true` 이고 대본 일본어 문장이 그대로(전각·반각·공백만 무시) 들어오면 Bedrock 없이 대본 일정을 새 `plan_id` 로 저장해 돌려준다. 로컬(`USE_MOCK=1`) 확인: 배지 해운대 🔴 · 빛축제 🔴 · 흰여울 🟡 → 빛축제 🔒 뒤 빛축제 `low` → 해운대 대안 광안리·송정 → 광안리 적용 뒤 해운대 배지 없음 → 되돌리기 원래와 같음. 마침표가 하나 빠진 문장은 캐시를 쓰지 않음. 배포 API 는 `deploy_api.ps1 -DemoCache true` 로 켜야 한다
- 빛축제 🔒는 화면에서 누른다 (노션 대본 수정함) — C
- `build_plan` 은 다음 Stop 시작을 `이전 끝 + 이동` 을 10분 단위로 올림만 해서 여유가 0~9분이다. Guardian 기준(`TRANSFER_BUFFER_MIN` 10분)과 맞지 않아 코드가 만든 일정에 처음부터 🟡가 붙는다. Guardian 기준을 내리면 4분 여유도 걸러야 해서 "빠듯한 이동" 점검이 의미가 없어지므로, `build_plan` 이 여유 10분 이상을 남긴다 — B → ✅ 완료 (#53). 다음 Stop 시작 = 올림(이전 끝 + 이동 + `TRANSFER_BUFFER_MIN`, 10분 단위)이라 여유가 항상 10~19분. `build_plan` 결과에 `check_plan` 을 돌려 `tight_transfer` 가 없는지 보는 테스트 추가. 샘플(감천 → 자갈치 → 부산타워 → 해운대)은 하루가 30분 늦게 끝남(16:10)
- 프론트엔드 `POST /plan/check` · `PUT /plan` · `POST /chat` 연결 (지금은 `GET /plan` 클라이언트만 있음) — C
